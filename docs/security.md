# 安全说明（astrolabe 0.5.6）

## 1. 威胁模型

| 威胁 | 面 | 现有防护 |
| --- | --- | --- |
| 不可信输入导致的回溯爆炸 | 组合子 | 显式 `commit` 语义：承诺后不再回退；`alt` 只回退到分支起点；`choice` 有序 |
| 超长输入 / 无界重复 | `many` / `take_while` | 组合子对输入做单遍扫描；`many` 每次迭代至少消费 1 字符则终止，零消费循环由调用方避免（见 §3） |
| 恶意输入触发 panic | 全库 | 解析失败返回 `ParseError`（`noraise`）；`parse_*_raise` 仅在调用方显式选择时抛出 |
| 错误信息泄露敏感内容 | `format_with_input` | 片段窗口有限（`ctx_start/ctx_end` 截取）；生产日志建议用 `format`（不含原文） |
| 依赖供应链 | 构建 | 运行时零 mooncakes 依赖（仅 MoonBit core）；`proof`/`benchmarks` 不进库运行时 |

## 2. 信任边界

- 库只做**纯字符串解析**：不读文件、不访问网络、不读环境变量、不持有密钥。
- 输入长度、分片、超时与内存上限由调用方控制；库不设隐式上限。
- 解析成功返回的值类型由调用方定义（`Parser[T]` 泛型），库不执行任何副作用。

## 3. 已知边界（真话）

- **零消费循环**：`many(pure(x))` 这类「成功但不前进」的组合会导致不终止——这是组合子库的通用约束；
  调用方应保证循环体至少消费一个字符（`take_while1` / `char` / `string` 均满足）。
- `format_with_input` 会在错误消息中包含输入片段；若输入含敏感数据，请改用 `format` 或在展示前脱敏。
- 段落/字素级语义不在库内（按 codepoint 推进），需要时由调用方预处理输入。
- 解析器只保证「按组合子定义的单遍扫描」，不承诺对抗**算法级**恶意输入（例如需要 O(n²) 的上下文相关文法由作者设计决定）。

## 4. 依赖与供应链

- 运行时依赖：MoonBit core（`moonbitlang/core/debug` 用于 `Debug` 派生）。
- 开发期依赖：Z3（仅 `moon prove`，CI ubuntu 安装）、Node（脚本门禁）。
- 第三方组件与许可证见仓库 `LICENSE`（MIT）。

## 5. 漏洞报告

请私密联系维护者（见仓库 `CONTRIBUTING.md` / GitHub Security Advisories），附最小复现：
输入串 + 组合子定义 + 期望/实际行为。请勿在公开 issue 披露可利用细节。
